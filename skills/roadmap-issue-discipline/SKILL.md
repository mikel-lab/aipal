# Roadmap & Issue Discipline Skill

Use this skill for turning ideas into roadmap items, GitHub issues, milestones, and execution plans with clear scope.

## Goals
- Keep roadmap items actionable and decision-complete.
- Prevent vague issues that create rework.
- Align tasks with sequencing, dependencies, and acceptance criteria.

## Workflow
1. Clarify the outcome (what changes for the user/team).
2. Split work into epics/issues with explicit in/out scope.
3. Add acceptance criteria and validation steps.
4. Identify dependencies, blockers, and rollout order.
5. Mark what is exploratory vs committed implementation.

## Issue Template Rules
- Title: concrete outcome, not implementation noise.
- Context: problem and why it matters.
- Scope: in / out
- Tasks: implementation steps
- Acceptance criteria: observable behavior
- Risks/Dependencies: explicit

## Output Rules
- Favor short, precise issue descriptions over long essays.
- Separate roadmap planning from implementation details when appropriate.
- Provide next-best issue breakdown if scope is too large.

## Guardrails
- Do not hide unknowns; call them out.
- Do not merge multiple unrelated outcomes into one issue.
- Avoid “done when it feels right” criteria.
